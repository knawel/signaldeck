# Design Decisions

This file records decisions so that discussions, firmware changes, and hardware revisions do not silently change the project architecture.

Statuses:

- **Accepted** - current design direction
- **Prototype** - current experimental choice; may change
- **TBD** - intentionally undecided
- **Deferred** - not part of the current milestone

| Area | Decision | Status | Rationale |
|---|---|---|---|
| MCU | Waveshare RP2040-Zero | Accepted | USB-C, RP2040 ecosystem, compact, programmable and already suitable for experimentation |
| External connection | Single USB-C for audio + power | Accepted | Simple desktop device with one cable |
| USB audio | USB Audio Class | Accepted | Standard host audio-device behavior |
| Initial format | Stereo 24-bit / 48 kHz | Prototype | Keep firmware/debugging manageable before increasing sample rate |
| DAC | PCM5102A module | Prototype | Simple I2S DAC, inexpensive and modular |
| DAC clocking | No external MCLK: SCK tied to GND, PCM5102A internal PLL | Accepted | Works on the prototype; avoids generating MCLK on the RP2040 |
| I2S format | Standard I2S (FMT low), 32-bit slots, generated by PIO + DMA ping-pong | Accepted | RP2040 has no I2S peripheral; I2S chosen over left-justified in lab 7 |
| USB clock sync | Asynchronous isochronous endpoint with explicit feedback, P controller on the FIFO level | Accepted | Keeps the DAC clock fixed and clean; host adapts its packet sizes (lab 8) |
| USB IDs | 0xCAFE:0x4008 (TinyUSB test vendor ID) | Prototype | Fine on one desk; a real VID/PID is needed before sharing the device |
| Interim volume | Digital −24 dB (`OUTPUT_SHIFT 4`) until the firmware volume exists | Prototype | Music at 0 dBFS is far too loud for earbuds straight from the module |
| Volume | Endless rotary encoder (no push switch) + firmware gain; total gain = host volume (UAC2 Feature Unit, OS slider) × knob; safe default at power-up | Prototype | Endless knob, works independently of the OS while the OS slider works too; 24-bit samples in 32-bit DAC words lose nothing audible. Replaces the analog 10k pot (2026-11-15) |
| Headphone outputs | 3.5 mm + 6.35 mm TRS, sockets with switch contacts | Accepted | Primary product requirement; switch contacts allow headphone detection |
| Headphone amplifier | Stage 1: NJM4556A gain-1 buffer, single filtered 5 V, capacitor-coupled output, relay mute (breadboard). Stage 2: OPA1622 + LM27762 (±~4.5 V, ground-referenced) on a small amp PCB (hw P2) | Prototype | NJM4556A is cheap, fast and fully hand-buildable for learning and firmware bring-up; OPA1622 gives ~2 Vrms, no output caps, built-in pop control (2026-11-15) |
| Amp input / interface | Amp input = PCM5102A line output, gain 1, input impedance >= 10 kOhm. Amp is a module on one connector: switched 5 V, GND, L, R, audio GND, AMP_EN, AMP_MUTE, optional AMP_PG; headphone jacks live on the amp module | Prototype | Lets the NJM4556A stage be swapped for the OPA1622 board without touching the DAC or audio firmware; firmware hides the difference behind amp_on()/amp_off() |
| Headphone load target | Rated for 32 Ohm and above (ATH-M40x 35 Ohm, DT770 Pro 80 Ohm); 16 Ohm tolerated at reduced output without damage | Accepted | Full 16 Ohm drive would double the current needed from a 5 V USB rail; the actual headphones are 35 and 80 Ohm (2026-11-15) |
| Mute | Not in the first design; later a separate front-panel button or switch (+ optional Feature Unit mute for the OS key) | Deferred | Keeps the knob and first firmware simple (2026-11-15) |
| Line output | Whether to add one for active speakers; with firmware volume it follows the knob; option: mute it when a headphone is plugged in | TBD | Does not block the amplifier work; the DAC output pins are the connection point either way |
| Level indication | Two physical L/R analog meters | Accepted | Functional level display and core industrial/instrument aesthetic |
| Meter signal | Computed in firmware from the samples before the knob volume; PWM → RC filter → current driver | Accepted | Meter independent of listening volume, nothing on the analog audio path, smoothing in software (2026-11-15) |
| Status indicators | USB + AUDIO | Prototype | Avoid unnecessary front-panel clutter |
| Power | DAC always on from board 5V; amp + meters on a soft-start switched rail (AUDIO_EN GPIO); front toggle read by firmware, which sequences rail and mute | Prototype | Keeps USB enumerated, never drives I2S into an unpowered DAC, limits USB inrush, no thumps (2026-11-15) |
| Mechanical design | Two metal front subpanels | Accepted | Aircraft/instrument-panel visual language |
| Leather | Red leather as enclosure/accent material | Prototype | Reuse existing material without compromising control mounting |
| Microphone input | Reserve as future expansion | Deferred | Useful feature but adds ADC, preamp and USB capture complexity |
| Versioning | Product V1/V2, hardware P1…/A…, firmware SemVer 0.x; version set once in CMake (`docs/versioning.md`) | Accepted | Keeps generation, board and firmware numbers from being confused; one source of truth for the number |
| Custom PCB | First a small amp board (OPA1622 + LM27762, hw P2); full device PCB after the modular prototype works | Deferred | Avoid debugging USB, DAC, analog and PCB layout simultaneously; the amp board is small and swappable |
